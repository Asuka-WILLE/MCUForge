# 预期的需求草案结构

Lead 的具体措辞可以不同，但在用户明确批准前，应只输出 `INTAKE_DRAFT`，不得派发 Worker、生成补丁或写源码。

草案至少包含：

1. **用户目标**：为电脑控制帧增加断链、急停和受控恢复。
2. **当前现象**：最后一条输出会被保持。
3. **拟议行为**：150 ms 超时清零并进入 FAILSAFE；急停清零并锁存；连续 3 帧中位恢复。
4. **验收条件**：超时、急停、恢复和正常路径都有可判断结果。
5. **非目标**：SBUS、RS485、真实电机逻辑、固定测试均不改。
6. **影响范围**：仅 Profile 白名单中的 Demo 安全控制文件。
7. **验证证据**：实际 diff、测试完整性、Keil 构建、HEX/AXF SHA；硬件未跑则明确未验证。
8. **风险**：时钟基准、帧有效性定义、恢复条件与现有状态机冲突。
9. **待确认问题**：若上下文已明确，不要重复问；确有歧义才列出。

末尾应提示用户可以修改草案，并说明只有“可以了，开始执行”“确认执行”或“开始执行”才会正式协作。单独回复“好”“继续”不能触发执行。
